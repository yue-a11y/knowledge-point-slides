# 反例库：实测踩到的 27 种翻车形态（含公式预备段 7 条、公式排版 3 条）

每条格式：**错的样子 → 为什么错 → skill 里哪条规则会拦 → 正确写法**。
开工前读一遍，交付前对着扫一遍。示例取自「LSV → Tafel 斜率」那次交付，规则本身与学科无关。

## 0-A. 公式排在系统字体里，下标写成 `E_eq`

- **错**：`<div class="formula">η = E − E_eq</div>`，字体跟正文同一个 `system-ui`，下划线原样留在页面上。
- **为什么错**：观众一眼就知道那是代码写法的复制品，不是「一行式子」。手写数学里变量斜体、下标下沉，
  而系统字体的 `_` 是打在基线上的等宽符号，读起来像变量名 `E_eq`。
- **拦它的规则**：C9（缺 `@font-face DeckMath` / 没内嵌 base64 / `.formula .expr` 没用 `var(--math)` = error；
  公式区出现 `X_y` = warn）。
- **改**：`scripts/make_mathfont.py` 生成数学子集并内嵌（正文手写体由 `embed_text_font` 按 deck 字符集生成）；`mathrender` 把 `j_0` 排成真下标；
  `sub, sup { font-size: .72em; line-height: 0 }` 防止把行高撑大。

## 0-B. 复算表一展开，下半截不见了

- **错**：末页把 `fig_sweep`（356px 高的图）+ 13 行 `details.recalc` 放在一起，屏幕态折叠着看不出问题；
  讲到那一页点开「数值复算」，表从第 2 行起就被 `overflow: hidden` 裁掉。
  打印版更隐蔽：weasyprint 不涨页数，`pdfinfo` 仍是 12 页，但第 12 页只剩一行。
- **为什么错**：`.slide` 是 `height: 900px; overflow: hidden`，折叠块展开只是改变内部高度，
  溢出的部分既不出滚动条也不报错；而所有校验都只在折叠态量过 `scrollHeight`。
- **拦它的规则**：C10（复算表与图同页且 >8 行 = error）+ `tools/shoot_deck.py` 展开态复测
  （逐页 `details.open = true` 再量 `scrollHeight - clientHeight`，>1px 报 `✗ 展开后溢出`）
  + 打印页数核对。
- **改**：复算表单独成页（`<details class="recalc" open>`，默认展开——折叠着的末页是空白页）；
  同页有图时推导步数 ≤6；展开态 `shoot_deck.py` 全绿后再导 PDF。

## 1. 线性图上说「变平」

- **错**：第 1 页画线性 j–E 曲线，标注「0.26 V 之后变平」。
- **为什么错**：「变平」是转成 Tafel 图（log j–η）之后才成立的判断。只看第 1 页的人不知道 Tafel 图存在，这句话无从验证。
- **拦它的规则**：R6（出现「变平/弯曲/偏离直线/拐点/线性区」的页，纵轴必须是 log）。
- **改**：第 1 页只说「j 增长变慢（传质开始起作用）」；「偏离直线」留到纵轴取对数的那一页再说。

## 2. 近似式子与数值各算各的

- **错**：BV 方程写 `j ≈ j₀ exp(α_a Fη/RT)`，注释「还原项/氧化项 ≈ exp(−Fη/2RT) = 3×10⁻³」；后面又用 b = 60 mV/dec 反算出 α_a ≈ 0.99。
- **为什么错**：`exp(−Fη/2RT)`（η = 0.15 V）等于 5.4×10⁻²，不是 3×10⁻³；3×10⁻³ 对应的是 `exp(−Fη/RT)`。而且同一个 docx 里隐含了两个 α_a（0.5 和 0.99），互相矛盾。
- **拦它的规则**：D1/D2 + 验收 I（`details.deriv` 里写代入值 + `details.recalc` 表 + 单参数贯穿）。
- **改**：写「还原项/氧化项 = exp(−Fη/RT) = 2.9×10⁻³（与 α 无关，因 α_a + α_c = 1）」，并全篇只用一个 α_a。

## 3. 换坐标只改曲线，不改标签

- **错**：第 2 页说「横轴换成 η」，第 3 页起曲线换了，但轴标签还是 `E vs RHE [V]`。
- **为什么错**：观众读的是标签，不是你的旁白。标签不改等于没换。
- **拦它的规则**：R2（标签的量必须等于 `data-x`）、R3（图内残留旧量名 + 缺 `recast`）。
- **改**：`data-x="η"` + `<text class="ax" data-axis="x">η [mV]</text>` + 刻度 + 图注 + 正文 + 一行 `recast`。

## 4. 第 1 页放后文才用得上的图，配一个对讲解没帮助的动画

- **错**：第 1 页标题讲「尾段已经在弯」，图是第 4 页的「两个禁区」图；第 4 页又放了一个把禁区扫一遍的动画。
- **为什么错**：起点页的任务是让人认出「这就是我手上那张图」；提前出现的标记会让人以为那是已知信息。动画扫禁区没有产生任何一个可算的量。
- **拦它的规则**：R8（第 1 页不许有 `data-anim`、`.dim`）、R9（动画必须绑住公式里的量）、R11（`origin` 只在第 1 页）。
- **改**：第 1 页只放原图 + 一句图上可见的事实；禁区页用静态带 + 三个判据，不用动画。

## 5. 全篇没有页码

- **错**：12 页没有一处 `N / M`，讲的时候只能说「刚才那一页」。
- **拦它的规则**：R1。
- **改**：每页 `<span class="pg">4 / 12</span>`，且与 `data-page`、总页数一致。

## 6. Δ 标注画反

- **错**：x 轴是 η、y 轴是 log j，却把 `Δlog j` 画成横边、`Δη` 画成竖边。
- **为什么错**：斜率的定义就是「竖边除横边」。画反了，观众照着图算出来是 b 的倒数。
- **拦它的规则**：R4（`data-span="x"` 的标注量必须等于 `data-x`）。
- **改**：`<g class="dim" data-span="x" data-sym="η">Δη = 100 mV</g>`、`<g class="dim" data-span="y" data-sym="j">Δlog₁₀ j = 1.667 dec</g>`。

## 7. 对数轴写成「j（对数）」

- **错**：纵轴标签 `j [mA/cm²]（对数）`。
- **为什么错**：标签是「量 + 单位」。刻度类型不是单位的一部分；写成括号注释后，读图的人得猜刻度上那个 `10⁻¹` 是 j 还是 log j。
- **拦它的规则**：R2（log 轴标签必须含 `log₁₀`，不许出现「对数」）。
- **改**：`log₁₀ j [mA/cm²]`。

## 8. 把移项后的同一关系再编一个式号

- **错**：式 (1) `η = b·log₁₀(j/j₀)`；式 (4) `log₁₀ j₀ = log₁₀ j − η/b`。
- **为什么错**：同一个关系的两种写法，观众要多记一个式子，却没有任何新信息。真正该给的是「j₀ 靠外推读」这一步的几何含义。
- **拦它的规则**：R5（全篇 ≤3 条、LHS 不许重复）。
- **改**：只留核心式，外推那页写「由式 (1) 取 η = 0 得 j = j₀」，并在图上画出外推虚线与截距。

## 9. 用同一张图讲两件事

- **错**：第 6 页用 slider 动画演示「区间上界变了 → b 变」；第 8 页讲「全段拟合会偏大」，用的还是同一张拟合图。
- **为什么错**：第二遍没有新增视觉元素，观众只会觉得「又在讲一遍」。
- **拦它的规则**：R10（两页的图不许几乎相同）、R9（同种动画只用一次）。
- **改**：错例页改成静态对比（正确区间 / 错误区间两条拟合线叠在一张图上，标出两个 b 值），并且不带动画。

## 10. 一页一个错例 + 讲错例的动画

- **错**：连续三页「全段拟合 → 75.7」「背景起拟合 → 64.3」「不补偿 → 66.8」，其中一页还把 marker 沿背景区拖了一遍。
- **为什么错**：错误应该在**第一次计算之前**用成立条件讲掉，而不是算完再逐个演示；marker 拖动没有产生任何可算的量。
- **拦它的规则**：R11（错例 ≤1 页、推导页不许出现「错误做法」）、R9（错例页禁止动画）。
- **改**：条件页写清三条成立条件 + 违反后图长什么样 + 判据；错例集中一页三段式；删掉 marker 动画。

## 11. 讲关键操作却不给公式

- **错**：第 10 页讲「不做 iR 补偿，右端右偏，b 报成 66.8」，全页没有一条公式。
- **为什么错**：iR 补偿本身就是一个式子（`E_meas = η_kin + R_u·j`）。不给式子，观众只能记住「要补偿」，不知道补多少、为什么右偏。
- **拦它的规则**：R7（讲「补偿/外推/换算/校正」的页必须有式，且式里的量能在图上指到）。
- **改**：给出 `E_meas = η_kin + R_u·j`，`R_u` 与 `j` 在图上标出，正文写「j 越大偏得越多 ⇒ 高电位端右偏 ⇒ 斜率被抬高」。

## 12. 页码写进 HTML 了，但屏幕上看不见

- **错**：每页都有 `<span class="pg">1 / 10</span>`，校验也过了，但在 1366×768 的窗口里右下角是空的。
- **为什么错**：版式是固定 1600×900 的绝对定位，却没做视口缩放。窗口小于 1600×900 时，右下角整块被裁掉——元素存在 ≠ 用户看得见。
- **拦它的规则**：R0（必须有 `transform: scale` / `zoom` + resize 监听；`.pg` 不许 `display:none`），验收 F 要求在 1280×720 下再看一次。
- **改**：`#deck { transform: scale(var(--k)) }` + `fit()` 里算 `k = min(innerWidth/1600, innerHeight/900)`，`resize` 时重算。

## 13. 末页挂例题/自测，或另起一页写「结论」

- **错**：最后 1–2 页是「自测：三道题」；或者前面算完，末页再来一页「结论 / 小结 / 总结」把话重说一遍。
- **为什么错**：这一版不要练习环节，也不要重复页——最后一个算例的标题已经写着这一步算出的数，
  再开一页总结等于把同一件事说两遍，还占掉一页。
- **拦它的规则**：D3（出现「自测 / 例题 / 习题」即 error；`summary` 已取消，出现即 error；
  末页必须是 `calc` / `pitfall`，末页标题含「结论 / 小结 / 总结 / 综上 / 回顾」即 error）。
- **改**：删掉自测页和结论页，让最后一个 `calc` 页把数与结论一并交代（标题写数，正文写这一数意味着什么）。

## 14. 推导里解释符号、或用「由式 (N) 得」代替推理

- **错**：
  ```text
  (2.1) η₂ − η₁ = b(log₁₀j₂ − log₁₀j₁)   依据：由式 (1) 得；其中 j₀ 为交换电流密度
  ```
- **为什么错**：①「其中 j₀ 为…」是符号说明，读者要的是这一步怎么算出来，不是名词表；
  ②「由式 (1) 得」把推导推给了上一条结论——读者回头翻上一页，仍然不知道这一步做了什么。
- **拦它的规则**：推导块里出现「由式」「由 (N.k)」「其中」「分别表示」「符号说明」即 error；
  形如「η 是…」「j 为…」的符号释义也会被正则抓到。
- **改**：把第 (1) 式的内容直接写出来再往下推——
  `η = b·log₁₀(j/j₀) 写两点：η₂ − η₁ = b(log₁₀j₂ − log₁₀j₁)，j₀ 相同，相减即消`，
  依据列写「代数：Tafel 形式在两点的差；假设 A1、A2 成立，故两点同 b、同 j₀」。

## 15. 推导挤在一页里，挤到删步骤

- **错**：为了守「每页一条公式、一屏放下」，把 6 步推导压成 3 行，中间变换全省。
- **为什么错**：讲解页的页数上限不是稀缺资源，省略的步骤才是。
- **拦它的规则**：D1 要求 ≥3 步且代数链条不断；页数**不设上下限**；
  推导可拆成 `data-eq` 相同、`data-part=2,3…` 的续页（第 1 片与公式同页，续页 `data-kind="calc"`）。
- **改**：一页写不下就续页，把每一步单独一行写出来。

## 16. 推导只写「定义 / 代数 / 量纲」三行

- **错**（真实产物）：式 (3) `b = Δη / Δlog₁₀ j` 的推导是

  ```text
  (3.1) η − η₀ = b·log₁₀(j/j₀)          依据：定义：Tafel 方程
  (3.2) b = (η₂−η₁)/(log₁₀j₂ − log₁₀j₁)  依据：代数：两点相减
  (3.3) 量纲：mV / dec                    依据：量纲检查
  ```

- **为什么错**：三行都在复述结论。读者想知道的三件事全缺——① 这式由哪条**已编号**的式变来（Tafel 方程在这份 deck 里根本没编号）；② 为什么相减能消掉 `j₀`、为什么窗口内可以当作直线；③ 本页那两个数（120 mV、0.95 dec）怎么变成 126 的，误差多大。
- **拦它的规则**：D1（≥3 步、依据落到具体来源、必须有一行数值代入、必须写误差/失效边界）；
  这条例子的正解是把它搬进预备段：首步依据写 `A3`，后面每步写「代数 / 量纲 / 近似及条件」。
- **改**：把推导写成五件事——由式 (N) → 相减消掉 j₀（同一直线同一截距）→ 代入 `(250−150) mV / 0.95 dec = 105 mV/dec` → 误差（端点读数 ±2 mV → ±2 mV/dec）→ 失效边界（窗口弯曲时得到的是弦斜率）。

## 16′. 引用的关系没有编号

- **错**：式 (3) 的依据写「定义：Tafel 方程」，但 Tafel 方程在这份 deck 里从没作为式 (1)/(2) 出现过。
- **为什么错**：读者无法回查，也无法判断这条式子和你后面用的式子是不是同一个。
- **拦它的规则**：D1 的「依据必须落到具体来源」+ 预备段 C4（首步依据必须是 A 编号或「定义」）。
- **改**：把真正在用的关系放进预备段（Tafel 方程占一条 P，从 BV 推出来），正文只写「依据：P2」。

## 17. 预备段抄了整页 BV 推导，正文却只用到 b = Δη/Δlog j（链条尾巴冗余）

- **错**：预备段用 12 步把 BV 一路推到 Tafel 方程、再推到 j₀ 的外推、再推到 α 的取值，正文只在第 9 页量了
  两条边 `b = Δη/Δlog₁₀ j`。
- **为什么错**：停点没定。预备段的终点是「正文最后一次代入这一式的那一步」，不是「把教科书那一章抄完」。
  多出来的 6 步占页数、抢注意力，还让听众以为 j₀ 后面要用。
- **拦它的规则**：`data-stop`（停点理由必须非空）+ C2（每条 P 的 `data-used-in` 指向的 calc 页必须真的引用它）。
- **改**：从终点量沿计算链往下走，走到第 9 页取窗口两端就停；把 j₀、α 的物理来源整段删掉，
  `data-stop` 写「正文最后一次代入在第 9 页取窗口两端；再往下是 α 的物理来源，不在本文档范围」。

## 18. 预备段只有一条总式，正文第 5 页冒出没定义过的 E₀ 或 α（闭包缺口）

- **错**：预备段只推了 `b = Δη/Δlog₁₀ j`；正文第 5 页为了讲「起始电位」写了个 `E₀`，第 7 页又冒出 `α`。
- **为什么错**：预备段的任务是让正文每个符号都有出处。总式只覆盖了它自己那几个符号，
  正文只要多用一个量，闭包就断了——听众只能猜这个符号是哪来的。
- **拦它的规则**：C1 孤儿符号闭包（`calc` 页的每个 `<var data-sym>` 必须属于某条 P 的 LHS/RHS，
  或起点图上的读数 `origin_reads`）。
- **改**：要么补一条 P（`η = E − E_eq` 就把 `E`、`E_eq` 都收进来），要么把这个量改成图上读得到的量。

## 19. 把「Tafel 方程 η = a + b log j」当公理写进 A 节，于是 P3 的 Δ 形式凭空出现（推论当公理）

- **错**：A 节写 `A3 [定律] η = a + b log₁₀ j`；P3 直接写 `(3.1) η₂ − η₁ = b Δlog₁₀ j  依据 A3`。
- **为什么错**：Tafel 方程在本文档之外有推导来源（BV + 高过电位近似），它是推论不是公理。
  把它塞进 A 节，等于把整条链的中间步骤删掉，P3 的两点相减就成了无源之水。
- **拦它的规则**：C4（首步依据必须命中 A 编号或「定义」——但 A3 本身是推论）+ C5（推论不许升格为公理，
  有推导来源的式子必须给推导）。
- **改**：A 节只留 BV（唯象公理）；Tafel 方程作为 P2 从 BV + 带数值的近似推出来；P3 首步依据写 `A3`（b 的定义）。

## 20. 预备段讲完符号含义，正文又讲一遍（符号说明回流）

- **错**：P1 页写「其中 η 为过电位、E_eq 为平衡电位」，第 7 页又写「η 表示过电位」。
- **为什么错**：符号含义只有一处能写——`<var data-sym>` + 单位行 + `.io` 行的「进/出」。
  写两遍不但占地方，还让听众以为第二遍有新信息。
- **拦它的规则**：预备段沿用「不许解释符号含义」（`其中`、`分别表示`、`… 为 …` 一律 error），
  `.io` 行强制写清输入量 / 输出量 + 单位。
- **改**：删掉两处文字释义，P1 页只留
  `<p class="io">吃进：E [mV]（第 5 页读得到）→ 吐出：η [mV]</p>` 与单位行。

## 21. 首页标题写「开讲前先钉死五条」（元话语）

- **错**：第 1 页标题「开讲前先钉死五条：A1–A5 之外不再假设任何东西」，下面还有一句 lead
  「Tafel 方程不在这五条里：它是 A3 加近似推出来的」。
- **为什么错**：这两句讲的是「本文档怎么组织」，不是知识点。听众要的是「过电位怎么定义、BV 长什么样」，
  不是讲解者的安排。念出来不产生任何可算的东西。
- **拦它的规则**：C6 元话语黑名单（开讲前 / 不再假设 / 本文档 / 为了讲清楚 / 本节只 / 后面会…），
  标题与正文都查。
- **改**：标题改成「三条定义、一条约定、一条定律」，下面直接 `<ol class="axioms">`；
  「Tafel 方程是 A3 推出来的」这句话本来就该由 P1 的推导说，不用在首页预告。

## 22. 把 η ≡ E − E_eq 挂 5 步推导，其中 3 步是代常数与换单位（定义当推导）

- **错**：预备段给「η ≡ E − E_eq」立了一个 P 页，推导写
  `(1.1) η ≡ E − E_eq（依据 A1）→ (1.2) E 取 vs RHE → (1.3) η[mV] = E[mV]（代数：×1000）→ (1.4) 代入 −0.100 V`。
- **为什么错**：这是定义，不是推导。5 步里只有换单位与代常数，删掉整页听众照样能读；
  它占掉一页、还把「预备段」变成「定义抄写」。
- **拦它的规则**：C7a（P 的式子归一化后等于某条 A → error）、C7c（真实变换 <2 → error）。
- **改**：η 的定义留在 A1；单位换算压成正文式 1 的「依据」一行；P 只留给真正推出来的式子
  （本仓库对照样本只剩一条 `b = Δη/Δlog₁₀ j`）。

## 23. A5 写「b ≡ 直线斜率」，于是 P3 的 Δ 形式凭空出现（推论当公理）

- **错**：A5 写成 `b ≡ 直线 η–log₁₀ j 的斜率`，P3 直接 `(3.1) η₂ − η₁ = b Δlog₁₀ j 依据 A5`。
- **为什么错**：`b` 是本文档要算出来的终点量，把它写进 A 节等于先给答案再「推导」。
  正确做法是让 A5 只含纯数学（`k = Δy/Δx`），`b` 在推导里由对照步定义出来。
- **拦它的规则**：C8a（A 的 LHS 是 `data-goal` → error）、C8b（A 之间互推）、
  C7b（推导照抄公理 ≥2 行）。
- **改**：`A5 [定义] 直线 y = kx + c 的斜率 k = Δy/Δx`；P1 里 `(1.5)` 与 A5 对照定出
  `k = 2.303RT/(α_aF)`，记 `b ≡ k`；`(1.6)` 两点相减，`(1.7)` 写成 `b = Δη/Δlog₁₀ j`。

## 24. 公式块整块倾斜，里面的推导表格跟着斜（1428px 宽差 7.5px）

- **错**：`.formula { transform: rotate(-0.3deg) }`，想做出「手写在纸上」的观感；推导表也在 `.formula` 里，
  于是表格横线两端差 `1428 × tan(0.3°) ≈ 7.5px`，肉眼可辨，PDF 里一样斜。
- **为什么错**：倾斜是**行内**排版效果，只能给式子那一行；块级容器一转，里面的表格、单位行、图注全跟着转。
  用 `boundingClientRect` 只看到变大的外接框，看不出倾斜，很容易漏。
- **拦它的规则**：C10（块级元素带 rotate/skew → error）+ `tools/measure_deck.py --tilt`
  （从 transform 链分解出实际角度，Δy = 宽 × tanθ，验收 ≤1px）。
- **改**：`.formula` 去掉 transform；`.formula .expr` 加 `transform: rotate(-0.3deg)`；
  `.units` 不再反向旋转（它已经不在旋转容器里）。

## 25. 手写体挂到含中文的元素上 / 子集字体没改名（换台机器字形就变）

- **错**：`.formula { font-family: var(--hand) }` 把整个公式块（含推导表、依据列）都设成手写体；
  子集只有 ASCII + 希腊字母 + 数学符号，中文全部回退到本机 LXGW WenKai。
  而且子集字体内部 name 仍是「LXGW WenKai」，`pdffonts` 里看不出哪份是内嵌、哪份是系统回退。
- **为什么错**：单文件的承诺是「公式字形自带」；回退到系统字体后，同一份 deck 在没装该字体的机器上
  会换字、甚至掉字。名字不改则连「有没有回退」都无法判定。
- **拦它的规则**：C10（`var(--hand)` 只许 `.formula .expr` / `ol.axioms .eq`）+ 字形覆盖检查
  （解 base64 读 cmap，公式元素里每个字符都要在子集里）+ `make_mathfont.py` 把 name 改成 DeckMath。
- **改**：公式挂 `DeckMath`、正文挂 `DeckText`，两套子集都内嵌；子集 name 分别改成 DeckMath / DeckText；
  验收用 `tools/measure_deck.py --fonts`（公式只报 DeckMath、正文只报 DeckText）与「屏蔽系统字体后逐像素比对」。

## 26. 公式退回平铺文本（`<sub>/<sup>`、`_` 拼接、`.mth` 定位 span）

- **错**：`η = b·log<sub>10</sub>(j/j<sub>0</sub>)`；或 `<span class="mth"><span class="scr sub">0</span></span>`
  先排好位置再写死；或者干脆把 `T_0`、`log₁₀` 直接当字符串写进页面。
- **为什么错**：三者都不是数学结构。`<sub>/<sup>` 嵌套时没有基线/字号规则（指数里再放下标就乱），
  定位 span 是像素级手排、改字就错位，`_` 与 Unicode 上下标根本没法逐层校验；
  它们都绕开了「变量 / 数字 / 运算符 / 上下标 / 分式」这一层结构，机器判不出对错。
- **拦它的规则**：C9（公式区域里不是恰好一个 `<math>`、`<math>` 外还有公式内容、`<math>` 文本里
  有 `_`/`^` → error）、C10（`.mth`/`.scr`、MathJax/KaTeX/polyfill/图片顶替 → error）、
  C11（公式外残留 Unicode 上下标 → error）。
- **改**：公式写成 DSL（`j = j_0 e^{η/b_a}`），由 `scripts/mathrender.py` 排成 Presentation MathML：
  变量 `<mi>`、数字 `<mn>`、运算符 `<mo>`、上下标 `<msub>/<msup>/<msubsup>`、分式 `<mfrac>`、
  根式 `<msqrt>`、中文注释 `<mtext>`。散文里的 `log₁₀` / `j₀` 由 `scaffold.subs()` 自动转成行内 `<math>`。

## 27. 拿 weasyprint 的 PDF 当公式观感对照

- **错**：`weasyprint -p deck.html shots/deck-print.pdf` 之后拿这份 PDF 判断「公式排得好不好」。
- **为什么错**：weasyprint 70.0 **不支持 MathML**（实测）：`<math>` 被当未知行内元素，
  上下标拍平、分式塌成一行、变量斜体丢失。它出的 PDF 公式全是错的，页数对不代表观感对。
- **拦它的规则**：打印源固定为 `tools/shoot_deck.py`（Chromium `page.pdf()`），
  `check_deck.py` 的截图检查要求 `shots/deck-print.pdf` 来自浏览器路径。
- **改**：观感只看 Chromium 屏幕截图与 `deck-print.pdf`（同一引擎）；weasyprint 仅用于页数交叉验证。

## 28. 分式写成一维斜杠 / 量纲排成二维 / 分母只框一个 token

- **错**（三种常见形态，全都亲眼见过）：
  1. 真分式写成斜杠：`η = b·log₁₀(j/j₀)`、`k = Δη/Δlog₁₀ j`、`η = (RT/α_aF)ln(j/j₀)`——
     斜杠两侧是**两个物理量**，却排成一行。
  2. 量纲写成二维：`mA/cm²`、`mV/dec` 被排成 `<mfrac>`（分数线的上下两个单位）。
  3. 分母只框一个 token：`\frac{RT}{α}_aF`（分母只有 `α`，`aF` 挂在分式外面）、
     `\frac{Δη}{Δ}log_{10} j`（`j` 掉在分母外）——看上去像分式，读起来是另一个式子。
- **为什么错**：一行斜杠在 1600×900 的投影上分不清分子分母到哪结束（`RT/α_aF·η` 到底是谁乘谁？）；
  量纲写成二维会让人把单位当成除法运算（`mA/cm²` 是一个单位，不是“mA 除以 cm²”）；
  分母只框一个 token 是最阴的错——**机器能看出分母不完整，读者却会按字面理解**。
  三者都绕开了「斜杠两侧是什么」这个可判定判据，变成人工目检。
- **拦它的规则**：C12（`check_deck.py` 的 `check_fraction_shape()`，全部 error）：
  `<mo>/</mo>` 两侧不是量纲词 → error；`<mfrac>` 分子分母都是量纲词 → error；
  `<mfrac>` 后面紧跟操作数（`mi/mn/msub/msup/mrow/mfrac/msqrt`）→ error。
  默认路径已经对齐：`mathrender` 的 `a/b` 自动出 `<mfrac>`，`scaffold.py` 的骨架里真分式就是二维。
- **改**：真分式写 `j/j_0`、`Δη/Δlog_{10} j`、`RT/α_aF`（不用手写 `\frac`，也不用给分母加 `{}`）；
  量纲照旧写 `mA/cm²`、`mV/dec`（两侧都是单位词，渲染器自动保留斜杠）。
  判据一句话：**把斜杠两侧念出来，是两个物理量就二维，是两个单位就留斜杠。**
