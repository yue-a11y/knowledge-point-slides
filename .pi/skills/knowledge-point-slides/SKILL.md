# 知识点讲解（HTML 版 PPT）

讲清**一个**知识点：听众听完能动手算、能判断、能反推。
这是讲解，不是名词解释、不是综述、不是文献汇报。

## 何时使用

- 用户说「讲清 XX」「XX 是怎么来的」「做个讲解 PPT」「备课讲一个知识点」「组会讲一下 Tafel 斜率怎么算」
- 需要「听完能做到某件事」，而不是「知道这个词是什么意思」

不适用：

- 名词解释、文献综述、论文汇报 → 用 `paper-to-cn-slides`
- 只要推导文档、不要幻灯片 → 直接写 markdown 后跑 `scripts/md2docx.py`
- 要 `.pptx` 文件 → 本技能只产单文件 HTML（Ctrl+P 导 PDF）

## 输入槽位

缺任何一项**先问，不要开写**：

| 槽位 | 要求 | 缺失时 |
|---|---|---|
| 知识点 | 一句话，具体到可判定（「LSV → Tafel 斜率怎么取」而非「电化学」） | 必须问 |
| 终点能力 | 动词句：能取 / 能算 / 能判 / 能反推 | 必须问，不要替用户定 |
| 听众 | 谁 + 已知 A、B + 不知道 C、D | 默认「同领域研究生，懂概念不会算」并明示 |
| 起点材料 | 形态 + 量纲 + 范围；第 1 页必须从它开始 | 必须问 |
| 终点量 | 结论 + 单位 | 必须问 |
| 贯穿算例 | 全篇唯一一组数 | 自造一组，页面上标注「示例数据」 |

硬规则：

- 全篇只用这一组数。任何一页出现这些数，必须完全一致、带单位。
- 没有实测依据的数字写 `[待补：来源]`，**不许补一个看起来合理的值**。
- 全程中文；术语首次出现给英文原词；同一概念全篇一个叫法，中途不换。

## 输出位置

```text
work/<slug>/                      # slug = 英文小写连字符
├── <slug>.html                   # 单文件幻灯片（最终产物）
├── <slug>-公式推导.docx          # 与幻灯片同批产出，不许后补

└── <slug>-交付说明.md            # 勾选结果 + 没做到的事
```

## 四道闸门（强制，不许跳阶段，不许一次回多个阶段）

### 闸门 1：只回 5 行，等确认

```text
起点：
终点：
听众缺：
贯穿算例：
最容易错的一步：
```

不写正文、不写大纲、不解释为什么这么设计。

### 闸门 2：只给 outline 表，等确认

表头固定，8–12 行：

```text
页码 | 这页让听众做什么判断 | 比上一页多/变了哪个视觉元素 | 一句话结论
```

- 第 1 页是起点那张图。
- 最后一页之前，每页都是对**同一张图的递进变形**，不是换一张新图。

### 闸门 3：视觉与动画计划 + 公式清单，等确认

```text
示意图：第 N 页手写内联 SVG，画什么
真实图：第 N 页引用 <文献> 图 <图号>（拿不到就写「拿不到」）
动画：第 N 页属于白名单第 ② 类，删掉会损失「区间边界」
公式：页 3 | 式 (1) | 由 Nernst 方程取极限
```

真实图拿不到时写「拿不到」，**不许用近似图顶替，不许 AI 生图当数据曲线**。

### 闸门 4：产出文件 + 自检全绿

按 `references/deck-contract.md` 的 HTML 契约写单文件 HTML，同时产出 docx，然后：

```bash
python3 scripts/check_deck.py work/<slug>/<slug>.html
```

**退出码 0 才算交付**。有 error 就改，不要解释为「模型限制」。

## 页面规范

- 一页一个动作。标题就是这页的结论，不是话题名（写「η 增大时斜率由 60 降到 40 mV/dec」而不是「Tafel 斜率讨论」）。
- 正文 ≤60 字/页，图为主；只出现当前这一步需要的公式。
- 阶梯必须完整：每步写清「输入 → 操作 → 输出 → 判据」，不跳中间步骤。阶梯讲的是「这一步在做什么」，不是代数推导。
- ≥3 条具名易错点，每条三段式：**错误做法 / 现象 / 正确做法**。写成「注意 XX」的视为没写。
- 末页 3–5 道自测题：≥1 计算、≥1 判断（给两张图选哪个做错了）、≥1 解释（数值变了意味着什么）。答案默认折叠。**不许出「你学到了什么」**。

## 动画白名单（只做这四类）

1. 坐标轴变换（线性 ↔ 对数、刻度重排）
2. 数据点沿曲线移动，标出当前取的区间
3. 拟合线扫过区间、几何量的边长标注出现
4. 参数滑块驱动图形与公式数值同步

判据：**删掉这个动画观众仍能理解 → 不做。**

禁止：入场动画、呼吸浮动、粒子背景、打字机、转场特效、无关 hover、emoji 当图标。

## 公式与推导

幻灯片里**不写推导**：

- 每页最多 1 条公式，带编号（式 1、式 2…，全篇连续）。
- 公式出现当页必须给出：每个符号的含义 + 单位 + 适用条件（如「η 较大、忽略还原项」）。
- 可以写「由式 (2) 取对数得式 (3)」，但不许把代数过程铺在页面上。
- 禁止出现「两边取对数」「代入整理得」「移项得」这类推导链。
- 依据最多一行：为什么取这一步（物理原因或近似条件）。

推导过程全部落进 `<slug>-公式推导.docx`：

- 式号与幻灯片一一对应，**同式一字不差**（以 docx 为准）。
- 每步只做一次变换，右侧注明依据（定义 / 近似及近似条件 / 代数 / 量纲检查）。
- 假设与近似条件在文首单列一节，编号 A1、A2…，正文引用编号。
- 量纲在首末两式各检查一次；近似在哪步引入、误差量级多少，必须写明。
- 幻灯片上指向 docx：涉及公式的那页标注「推导见 docx §N」。

生成 docx（LaTeX → Word 原生公式，需要 pandoc）：

```bash
bash scripts/get_pandoc.sh        # 首次：装到本项目 tools/pandoc/（约 140MB）
python3 scripts/md2docx.py work/<slug>/<slug>-公式推导.md work/<slug>/<slug>-公式推导.docx
```

pandoc 缺失时脚本自动降级为 python-docx（公式以 Unicode 文本插入，文首注明「公式不可编辑」）。

## 图与数据

- 示意图手写内联 SVG：可动、可控、无版权问题。
- 引用真实文献图必须标注出处（作者/期刊 + 图号）。
- AI 生成图不得充当数据曲线。
- 拿不到的材料就写「拿不到」。

## 交付形态

- **单文件 HTML，无外网依赖**：字体、脚本、公式全部内联；不用 CDN 的 MathJax / Chart.js。
- 键盘 ←/→ 与滚轮翻页；1 页 1 屏，任何页面不出现滚动条。
- 正文 ≥20px（1600×900 下）；层级 ≤3 级。
- Ctrl+P 导出 PDF 时每页一张、无内容截断。
- docx 与幻灯片同目录、同批产出。

HTML 骨架（`class` / `data-*` 是自检脚本的契约，不可改名）：

```html
<section class="slide" data-page="1">
  <h1>这一页的结论句</h1>
  <figure class="fig"><svg>…</svg></figure>
  <div class="formula" data-eq="1">…</div>
</section>
```

完整契约见 `references/deck-contract.md`。

## 验收（交付前逐条打勾，写进 `<slug>-交付说明.md`）

| 项 | 判据 | 谁来查 |
|---|---|---|
| A | 抽任意一页能说出它比上一页多了哪个视觉元素 | 人 |
| B | 用贯穿算例从第 1 页复算到末页，数值一致 | 人 |
| C | ≥3 条易错点，均为三段式 | 脚本 + 人 |
| D | 末页自测题含计算题、答案可折叠 | 脚本 + 人 |
| E | 断网打开，公式/图/动画正常 | 脚本 + 人 |
| F | 每页无溢出、无滚动条、字号达标（逐页截图核对） | 人 |
| G | 附每页缩略截图 + 勾选结果 + 「没做到的事」清单 | 人 |
| H | 每页公式 ≤1 条且带编号，无推导链，符号有含义与单位 | 脚本 + 人 |
| I | docx 推导逐式核对：一次一变换、式号对应、假设齐全 | 脚本 + 人 |

逐条细则见 `references/checklist.md`。「文件写完」不算交付；缺 G 视为未完成。

## 禁止

- 定义 → 公式 → 意义 → 应用 → 小结 四段式
- 每页「标题 + 3 个 bullet」
- 「谢谢观看」「欢迎提问」页
- 装饰性大图与渐变 hero
- 跳步直接给公式；幻灯片里铺推导（那属于 docx）
- 把推导塞进小字或备注糊弄过去
- 编造数值
- 只给源码不给截图
